## 2. 项目本质与核心难点

### 2.1 一句话概括

**输入歌名 → 查到歌号 → 调接口拿加密视频地址 → 下载 → 解密 → 转码 → 本地播放**。

### 2.2 三个核心难点

#### 难点 1：曲库搜索没有远程接口

上游**没有**提供「搜索歌曲」的 HTTP 接口。搜索完全依赖本地 SQLite 曲库（`muse.db`，983MB，70.7 万首）。

必须先从官方曲库服务下载这个库。

#### 难点 2：源站风控极严

歌曲源站（`zk.ktv1.top` 等）只放行「干净」请求：

```
GET /i.php?... HTTP/1.1
Host: zk.ktv1.top:6677
Accept: */*
```

**多一个字节都不行**。带上 `User-Agent`、`Connection`、`Accept-Encoding` 任何一个，立即 403「检测到异常行为」。

这也是为什么不能用 `HttpClient`（它无法完全去掉默认头），必须手写 HTTP 报文走裸 Socket。

#### 难点 3：视频是加密的 MPEG-TS

源站下发的是 **Thunder 加密的 MPEG-TS**：

- 前 512 字节是私有头
- 头[500..512] 是签名（`THUNDERCRYP3`）
- 密钥按 `头[53] & 0x0F` 从内置表取
- 分段用 AES-128-ECB 解密

而且 TS 里音轨是 **mp2**，直接塞进 MP4 会被标成 mp3，**绝大多数播放器静音**。

## 4. 外部接口完整清单

本项目共涉及 **6 组外部接口**。前 3 组是核心，后 3 组是辅助。

### 4.0 所有端点与凭据都在一个地方

下面各节出现的 appid / appkey / sdkkey / ver / vn / 设备 MAC 与 SN / 源站主机列表 /
mls-api 的登录与同步 URL / 伪造 IP / channel / mode / User-Agent / RSA 公钥，
**全部集中在 `Infrastructure/Config/ProtocolCredentials.cs`**，代码里不要再写第二遍。

早期这些常量分散在 `SongUrlService` 与 `DatabaseUpdateService` 两处，
改一个源站要翻两个文件、还容易漏；现在：

- 默认值以 `Default*` 常量的形式写在这个类里；
- 若存在 `%AppData%\KtvDownloader\credentials.json`，启动时按同名键覆盖；
- 覆盖文件坏了（非法 JSON）就静默回落到默认值，不会因为一个配置文件起不来；
- `ProtocolCredentials.BuildTemplate()` 会生成一份带说明的模板，照着填即可。

> 这也是为什么 §4.1~§4.7 里的示例值只是"当前内置的默认值"：
> 换源站、换设备号、换试用窗口都不需要改代码重新编译。

### 4.1 【核心】取 token —— `i.php`

**作用**：获取设备认证 token，是取播放地址的前置步骤。

```
GET http://{HOST}/i.php?{params}&sign={sign}
```

**常量**（硬编码在 `SongUrlService.cs`）：

```csharp
APP_ID  = "d4eeacc6cec3434fbc8c41608a3056a0"
APP_KEY = "024210cba40d4385a93e6c2d3249bfb5"   // i.php 签名盐
VER     = "4"
VN      = "4.100.5.11121504"
DEVICE_MAC = "9658dd1eafa73a55"
DEVICE_SN  = "0000037bb640"
```

**参数（顺序不能改）**：

| 参数 | 值 | 说明 |
|---|---|---|
| `appid` | APP_ID | 固定 |
| `mac` | `{MAC}_{SN}` | 设备标识，下划线连接 |
| `sn` | SN | 设备序列号 |
| `time` | Unix 秒级时间戳 | 当前时间 |
| `ver` | `4` | 协议版本 |
| `vn` | `4.100.5.11121504` | 客户端版本号 |
| `sign` | `MD5(上述整串 + APP_KEY)` | 签名 |

**签名算法（关键）**：

```csharp
// 不是按键排序！是把参数字符串原样拼接后加盐做 MD5
var parameters = "appid=...&mac=...&sn=...&time=...&ver=4&vn=...";
var sign = MD5(parameters + APP_KEY);   // 小写十六进制
```

**成功响应**：

```json
{
  "code": 200,
  "token": "MTAwMDAwMDAwMGYyM2Q2ZjFjNmRkOGZhMGY4NGU2ZTk=",
  "end_date": "2026-10-05 14:58:21",
  "ordertype": 0,
  "online_state": 0,
  "retry": 5,
  "msg": "ok",
  "heart_time": 5400
}
```

**注意**：
- `token` 含 `=`，后续拼参数时**必须原样带入**
- `end_date` 是试用窗口到期时间，过期后需换出口 IP
- token 可缓存重复使用（本项目按 host 缓存）

### 4.2 【核心】取播放地址 —— `do.php`

**作用**：按歌号拿到可下载的加密视频地址。

```
GET http://{HOST}/music/do.php?{params}&sign={sign}
```

**常量**：

```csharp
SDK_KEY = "19042303a8374f67ae3fe1e25c97936f"   // do.php 签名盐
```

**参数（顺序不能改）**：

| 参数 | 值 | 说明 |
|---|---|---|
| `appid` | APP_ID | 固定 |
| `device` | `{MAC}_{SN}` | 注意与 i.php 的 `mac` 不同名 |
| `ish265` | `0` / `1` | 是否请求 H.265 |
| `ls` | **`1`** | 固定，其它值会被风控拒绝 |
| `musicno` | 歌号 | 如 `7300654` |
| `resolution` | `480`/`720`/`1080` | 多数歌只有 480p |
| `sn` | SN | 设备序列号 |
| `time` | Unix 秒 | |
| `token` | 上一步的 token | 原样带入 |
| `sign` | `MD5(整串 + SDK_KEY)` | 签名 |

**成功响应**：

```json
{
  "code": 200,
  "data": "http://txog.ktvsky.com/264/lvbr/480/E/ts/52.4/202305092148/480p/7300654.ts?token=...&t=...",
  "msg": "SUCCESS",
  "limit": 2000
}
```

**失败响应**：

| code | 含义 |
|---|---|
| 400 | 缺少参数 |
| 403 | 检测到异常行为（风控限流） |

**关键处理**：
- 403 是**限流**不是 token 过期，等 3 秒用**同一 token** 重试
- 不要因为 403 就去重取 token（会放大请求量）

### 4.5 【核心】曲库同步 —— `mls-api/v1/sqlite/sync`

**作用**：获取曲库数据库文件信息。

```
POST https://mconn.cherryonline.cn/mls-api/v1/sqlite/sync
Cookie: muse-portal-connector=...
Content-Type: application/json; charset=UTF-8
```

**请求体**：

```json
{ "last_sync_at": 0, "music_file_type": 214 }
```

**成功响应**：

```json
{
  "errcode": 0,
  "errmsg": "OK",
  "files": [{
    "url": "https://ali.pri.mcdn.cherryonline.cn/muse.portal.ott_common.full.261119.db.gz?Expires=...&Signature=...",
    "md5": "BECA645F1CAB1800216934CE3A22462E",
    "date": 1795047075411,
    "day": "261119",
    "db_vc": 10100,
    "key": "muse.portal.ott_common.full.261119.db.gz",
    "music_file_type": 214,
    "type": 1,
    "id": "36350dcc-..."
  }]
}
```

**处理流程**：

1. 取 `files[0].url` 下载（约 **418MB gzip**）
2. 用 `md5` 校验
3. 解压得到 `muse.db`（约 **983MB**）
4. 原子替换旧库（先备份 `.backup`）
5. 版本号写入同目录 `db_version.txt`

**版本号优先级**：`date`（毫秒时间戳） → `day` → `db_vc`

**授权门控**：未授权设备 sync 返回空 `files` 数组。

|---|---|---|
| `name_trim GLOB '童话*'`（前缀） | **1-5ms** | 走索引 |

### 6.6 ITsDecryptService（Thunder 解密）

```csharp
Task<bool> IsEncryptedAsync(string filePath, CancellationToken ct);
Task<bool> DecryptAsync(
    string sourcePath, string outputPath,
    IProgress<double> progress, CancellationToken ct);
```

**加密格式规格**：

| 偏移 | 含义 |
|---|---|
| 头[500..512] | 签名：`THUNDERCRYP3` / `HHCMUSECRYP1` / `HHCMUSECRYP2` |
| 头[53] & 0x0F | 密钥索引（0-15） |
| 头[452] | 段大小（KB，通常 8） |
| 头[453] | 模式（仅支持 0） |
| 头[454] | 间隔（0=全加密，64=每 64 段加密一次） |
| 头[457] | 第一个加密段号（通常 3） |

**解密条件**：
- `interval == 0` → 全解
- 否则：`seg == first` 或 `(seg > first && seg % interval == 1)`

**算法**：每段用 **AES-256-ECB/NoPadding** 解密前 `(len - len%16)` 字节，尾部原样保留。

> ⚠️ 本节与 README 早期都写的是 AES-128，**是错的**：
> 内置密钥表里每一项都是 64 个十六进制字符 = 32 字节 = AES-256。
> `tests/KtvDownloader.Tests/TsDecryptServiceTests.cs` 里有一条断言把 32 字节钉死了。

**加密判定只看签名**：`IsEncrypted` 只检查 `头[500..512]` 是否命中三种已知签名。
早期实现是"首字节不是 `0x47` 就当加密"，而曲库里还有 1,157 首 `.mp3` 与
8,488 首 `.ls/.kls`（§5.4），它们首字节当然不是 TS 同步字节 →
被送去解密 → 签名不匹配 → 整首歌判"下载失败"。非 TS 内容一律原样透传。

### 7.1 CleanHttpClient —— 防风控 HTTP 通道

**为什么不用 HttpClient**：它无法完全去掉 `User-Agent` 等默认头。

**实现方式**：手写 HTTP/1.1 报文，走裸 Socket。

```csharp
// 实际发出的报文（仅此三行）
GET /i.php?appid=... HTTP/1.1
Host: zk.ktv1.top:6677
Accept: */*
\r\n
```

**实现要点**：
- 手动解析状态行、响应头、chunked 编码
- 支持 http 与 https（https 用 `SslStream`，证书验证全放行）
- 超时默认 10 秒

**验证过的事实**：带 `User-Agent` 请求同一 URL → 403「检测到异常行为」。

### 7.3 RsaPkcs1Encryptor —— 手写 RSA

**为什么手写**：net48 的 `RSA.EncryptValue` 只做裸模幂，不提供 PKCS#1 v1.5 填充。

**实现步骤**：

1. 解析 X.509 SPKI 的 DER 结构，取出模数 n 和指数 e
2. 组装 EM 块：`0x00 || 0x02 || PS(随机非零) || 0x00 || M`
3. 模幂：`c = EM^e mod n`
4. 补齐前导零到固定长度，Base64 编码

**net48 兼容坑**：
- `BigInteger` 不支持 `isUnsigned` / `isBigEndian` 构造（那是 .NET Core）
- 需自己写大端↔小端、无符号转换
- `GetBitLength()` 也不存在，用字节长度估算

```
第 2 条音轨 = 伴奏
```

| accomp 值 | 左声道 | 右声道 |
|---|---|---|
| `1` | 原唱 | 伴奏 |
| `2` | 伴奏 | 原唱 |

## 8. 踩坑记录

按严重程度排序。**这些坑都已踩过并解决，改动代码时注意不要退化。**

### 坑 1：mp2 音频塞进 MP4 会静音 ⚠️ 最坑

**现象**：转码出的 MP4 画面正常，**完全没有声音**。

**原因**：TS 音轨是 **mp2**。用 `-c copy` 直接塞进 MP4，容器标成 `mp3 (mp4a)`，但实际是 mp2 数据。Windows 自带播放器、电视盒子、多数手机**解不出来**。

**正确做法**：

```bash
# ❌ 错
-c copy

# ✅ 对：视频流拷贝，音频必须重编码为 AAC
-c:v copy -c:a aac -b:a 192k -ac 2
```

---

### 坑 2：取址接口带 UA 立即 403

**现象**：用 `HttpClient` 请求 `i.php` 一直 403。

**原因**：源站风控只放行「干净」请求。

**正确做法**：手写 HTTP 报文，只发 `Host` + `Accept: */*`。

---

### 坑 3：签名不是按键排序

**现象**：sign 计算错误，返回「签名错误」。

**原因**：以为要按键名字母序排序（常见 API 惯例）。

**正确做法**：

```csharp
// 参数按固定顺序拼成字符串，然后直接加盐 MD5
var sign = MD5("appid=xxx&mac=xxx&sn=xxx&time=xxx&ver=4&vn=xxx" + APP_KEY);
```

**参数顺序也不能变**。

---

### 坑 4：token 里的 `=` 要原样带入

`i.php` 返回的 token 形如 `MTAwMDAwMDAwMGYyM2Q2ZjFjNmRkOGZhMGY4NGU2ZTk=`，含 `=`。

拼进 `do.php` 参数时**不能 URL 编码**，要原样带入，签名也要用原样字符串算。

---

### 坑 5：IE11 也不支持 MPEG-TS

**现象**：预览黑屏，报「不受支持」。

**原因**：最初用 `WebBrowser + <video>` 方案。即使注册了 IE11 模式，IE 的 `<video>` 也**不支持 MPEG-TS 容器**，而且文件还是加密的。

**正确做法**：换 libVLC。VLC 原生支持 TS，解密后直接播，**无需转码**。

---

### 坑 6：下载 CDN 会间歇 502

**现象**：某些歌莫名其妙「转码失败」。

**原因**：CDN 返回 502，旧代码一次失败就判定整体失败。

**正确做法**：加 `RetryPolicy`，5xx/429/408 自动重试 3 次（2s/4s/8s 退避）。

---

### 坑 7：歌手名子查询拖慢搜索 450ms

**现象**：搜索要 880ms。

**原因**：

```sql
-- 每行都跑一次关联查询，50 行 = 50 次
(SELECT group_concat(sg.name,'/') FROM song_singer_relations r ... WHERE r.song_id = s.id)
```

**正确做法**：先取歌曲，再用一条 `IN` 查询批量补歌手名（450ms → 2ms）。

---

### 坑 8：`ORDER BY rec_score` 让索引失效

**现象**：即使加了索引还是全表扫。

**原因**：`rec_score` 在 707,138 首里只有 24 首非 NULL，SQLite 无法用它走索引。

**正确做法**：排序改为 `ORDER BY hot_score DESC, name ASC`。

---

### 坑 9：`LIKE '%xx%'` 全表扫 400ms

**现象**：中文搜索慢。

**原因**：中间匹配无法用索引。

**正确做法**：两阶段搜索，先用 `GLOB 'xx*'` 前缀匹配（1-5ms）秒出首屏，后台再补完整结果。

---

### 坑 10：`OnLoad` 里弹模态框卡住窗体

**现象**：程序启动了但窗口不显示，进程活着、`MainWindowHandle = 0`。

**原因**：在 `OnLoad` 里同步调 `MessageBox.Show`，阻塞了窗体的首次显示。

**正确做法**：

```csharp
protected override void OnLoad(EventArgs e)
{
    base.OnLoad(e);
    InitializeControls();
    BeginInvoke(new Action(CheckDatabase));   // 延后到消息循环启动后
}
```

---

### 坑 11：libVLC 音轨 id 只能问 libVLC 要，不能猜

**现象**：`SetAudioTrack(1)` 返回 false；或者"伴奏"点了没反应，一直在放原唱。

**原因**：
- `libvlc_audio_set_track(player, id)` 要的是 libVLC 内部的音轨 id，
  在 MPEG-TS 场景下就是 **PID**（257、259 这种），不是 1/2/3 这样的序号；
- `libvlc_audio_get_track_id` **在 libvlc 3.x 里不存在**（早已废弃的 0.9 API），
  P/Invoke 它只会得到 `EntryPointNotFoundException`；
- 曾经的做法是"以当前 PID 为基准递推 `current + i`"，
  但 TS 的音轨 PID **不保证连续**（实测 257/259，中间那条被解码器占掉了），
  递推出的第二个 id 指向不存在的音轨 → `set_track` 返回 0 → 切换静默失败。

**正确做法**：调 `libvlc_audio_get_track_description(player)` 拿真实的描述链表，
遍历 `{ int i_id; char* psz_name; struct* p_next; }`，`i_id` 就是要传给
`libvlc_audio_set_track` 的值；`i_id == -1` 那条是「禁用音频」，要过滤掉。
链表是 libVLC 分配的原生内存，**必须**用 `libvlc_track_description_list_release` 释放。

见 `Infrastructure/Media/VlcMediaPlayer.cs` 的 `GetAudioTrackDescriptions()`。

---

### 坑 12：NuGet libVLC 强制带 x86

**现象**：发布包 249MB，想排除 x86 但 csproj 的 `Remove` 无效。

**原因**：NuGet 的 targets 在 Copy 阶段强制复制。

**正确做法**：用构建后 Target 删除：

```xml
<Target Name="RemoveX86LibVlc" AfterTargets="Build">
  <RemoveDir Directories="$(OutDir)libvlc/win-x86" ContinueOnError="true" />
</Target>
```

省 96MB（249MB → 154MB）。

---

### 坑 13：程序开着时编译会文件锁定

**现象**：`MSB3021: 无法复制文件，文件被 KtvDownloader.exe 锁定`。

**正确做法**：编译前先关掉程序：

```powershell
Stop-Process -Name KtvDownloader -Force -ErrorAction SilentlyContinue
```

**更好的做法**：直接用 `.\scripts\build.ps1`，它每次构建前都会自动做这一步
（`-NoKill` 可以关掉这个行为）。CI 上是全新 runner，不存在这个问题。

> 顺带一提：`Stop-Process -Force` 有可能正好打断 `ConfigStore` 写配置。
> 现在写入是 `.tmp` + `File.Replace` 的原子操作，被打断最多丢掉这次改动，
> 不会再把 `config.json` 留成 0 字节（见 §9.3）。

### 9.3 首次运行配置

配置存在 `%AppData%\KtvDownloader\config.json`：

```json
{
  "DatabasePath": "E:\\Program Files\\KTvDownload\\muse.db",
  "OutputDirectory": "C:\\Users\\<user>\\Videos\\KtvDownloader",
  "FfmpegPath": "",
  "MaxConcurrency": 2,
  "DefaultResolution": "720",
  "DefaultVocal": 0,
  "ConvertToMp4": true,
  "PageSize": 50,
  "PreviewDurationSeconds": 60,
  "LogLevel": "Debug"
}
```

**写入是原子的**：先写 `config.json.tmp` 再 `File.Replace` 换过去。
早期是直接 `File.WriteAllText`（先截断再写），如果这时候断电或者被
`Stop-Process` 干掉（坑 13 就是让人这么干的），config.json 会停在 0 字节，
下次启动解析失败 → 静默回落默认配置 → 用户设的下载目录、曲库路径全没了，
而且界面上完全看不出来。

**非法值会被夹回合法范围**（`AppConfig.Normalize`）：

| 项 | 合法范围 | 越界时 |
|---|---|---|
| `MaxConcurrency` | 1-8 | 夹到边界 |
| `PageSize` | 10-500 | 夹到边界 |
| `PreviewDurationSeconds` | 0（完整下载）或 10-600 | 1-9 会被抬到 10（太短的切片凑不齐一个 TS 关键帧，VLC 会黑屏） |
| `DefaultVocal` | `VocalOption` 里定义过的值 | 回落 `KeepBoth`（不再直接强转，避免非法枚举值一路传到 ffmpeg 参数拼装才炸） |
| `LogLevel` | Debug / Info / Warn / Error | 回落 Debug |

**曲库自动探测顺序**（`DatabasePathResolver`）：

1. 配置里已保存的路径
2. `%AppData%\KtvDownloader\muse.db`
3. **从 exe 所在目录逐层向上**查找 `muse.db`（最多 8 层）
4. 当前工作目录

所以把 `muse.db` 放在项目根目录，程序会自动找到。

### 9.4 日志

`%AppData%\KtvDownloader\logs\yyyyMMdd.log`，按天切分，保留 14 天。

**写入是缓冲的**（常驻 `StreamWriter`，不再每条日志 `File.AppendAllText` 一次），
刷盘时机：WARN/ERROR 立刻刷（这类日志往往紧跟崩溃，不能丢现场）、
攒够 64 行、跨天切文件、显式 `Flush()`、`Dispose()`。
程序退出时 `Program.Main` 的 `finally` 会 Flush + Dispose。

**级别可配**：`config.json` 的 `LogLevel` 设成 `Warn` 能少写约七成行。
**全局只有一个 `FileLogger` 实例**（`Program._logger`）——
早期异常兜底里又 `new` 了一个，两个实例抢同一个 .log 文件，
恰好会让"崩溃时的最后一条日志"写不进去。

早期 `Properties/AssemblyInfo.cs` 把它钉死成 `1.0.0.0`，
于是拿到一份日志根本分不清用户跑的是哪次构建。
